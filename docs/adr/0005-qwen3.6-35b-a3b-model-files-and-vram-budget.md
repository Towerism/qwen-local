# ADR 0005: Qwen3.6-35B-A3B model files and VRAM budget

- **Status:** Proposed
- **Date:** 2026-11-04

## Pinned files

The main file and the multi-token prediction (MTP) draft file come from two Hugging Face repos, each at its own revision. `qlm fetch` downloads each from `https://huggingface.co/<repo>/resolve/<revision>/<path>` and checks these hashes. Changing a pin needs an update to this ADR.

## Measurements

Measured on 2026-11-04 on the RTX 4090 (24,564 MiB) with llama.cpp b11669 (`620d2225c`). With qlm-server stopped, the desktop held 1,478 MiB, which leaves 22.5 GiB. The load log reports `n_ctx_train = 262144` and 40 blocks (`qwen35moe`, 256 experts, 8 used per token). The main file and the MTP draft both load on this build, and the main file's weights take 19,903 MiB on the GPU.

A configuration fits when it starts, `qlm smoke` passes, and its peak VRAM from `qlm bench --quick`, rounded up to 0.1 GiB, plus the 0.5 GiB that `qlm start` keeps free, is at most the 22.5 GiB beside the desktop. Rounding first means `qlm start` accepts the profile's `vram_gib` on this desktop.

**MTP is on in agent.** The draft loads on b11669 and agent reaches 49,152 tokens with it at `--n-cpu-moe 0`, above the 32,768 floor, so the MTP fallback doesn't apply. MTP makes code generation 1.76 times and prose 1.36 times faster, for 1.1 GiB of VRAM. Long runs MTP off, like the 27B long profile; keeping 4 layers of experts in system RAM is what lets it hold the full 262,144 tokens, at 40 to 55% of agent's generation speed.
